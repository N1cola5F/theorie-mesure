# 更新记录与维护约定

当前版本：**v1.6.0**  
发布日期：**2026-10-09**（Asia/Shanghai）

本文件记录课程资料、转写文件和学习解答的内容更新。原始课程资料与自行编写的解答分别标识；课程文件自身的日期不等于本仓库的入库日期。

## 版本与记录规则

- 使用 `v主版本.次版本.修订号`：目录结构或维护规则发生不兼容调整时升主版本；新增一周资料、官方答案或一组解答时升次版本；纠错、排版和不扩展范围的修订时升修订号。
- 一次整理作为一个发布版本。新记录写在最上方，包含日期、输入变化、输出变化、修正、验证和已知边界；进行中的工作写在“未发布”。同一天的后续独立修改继续递增版本号。
- 不根据文件修改时间编造历史。本地课程目录的早期记录没有 Git 历史；v1.0.0 是根据已有说明文件补录的历史基线，v1.1.0 是首次正式登记版本。自 v1.6.0 起另以 GitHub 提交记录在线发布。
- 原始 PDF 保留原名和内容。生成答案的截题只作用于新成品，不覆盖或裁切原始题单。
- 每次发布保存 `维护记录/版本清单/v版本.json`，登记来源文件、输出文件、页数、大小和 SHA-256。清单用于识别新增及改动，不等同于版本备份；替换原文件前应另存旧版。
- 文件清单不递归收录自身；临时渲染图和编译缓存不作为课程内容更新。

## 下一次更新的操作顺序

1. 将新原始文件放入对应周次；官方答案放入该周 `corrige/`，保留原名。
2. 对照最近版本清单，列出新增、修改、移除和重命名项。发现路径未变但 SHA-256 改变时，明确写“替换/修改”，不要当作原文件未变。
3. 先阅读题单、讲义和可用官方答案，再更新派生成品及可编辑源文件；注明解答的覆盖题号和所用定义。
4. 完成必要编译及与实际改动相关的检查，遵循用户当次核验范围，不默认截图或逐页复核；将实际结果写入对应校验记录。
5. 在本文件新增版本记录，更新根目录索引和版本清单；不得覆盖旧版本清单。[snapshot.py](历史记录/snapshot.py) 会拒绝覆盖已有版本，并可对照上一份清单列出新增、修改与移除文件。例如完成下一次修订后运行：

    python 维护记录/snapshot.py v1.5.1 --date YYYY-MM-DD --previous 维护记录/版本清单/v1.5.0.json

脚本依赖 Python 与 pypdf；版本号和日期应替换为实际发布值。快照在全部文档和校验记录写好后生成，避免清单哈希立即过期。

新增记录模板：

```markdown
## vX.Y.Z — YYYY-MM-DD

### 输入变化
- 新增 / 修改 / 移除 / 重命名：路径、内容、来源。

### 输出变化
- 覆盖题号、语言、格式、源文件、具体修正。

### 验证与边界
- 实际执行的检查与结果。
- 未覆盖的内容或待核实事项。
- 版本清单链接。
```
